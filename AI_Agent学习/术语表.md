# 术语表

自学时碰到名词，先来这里对一下，再回课文。每条只保留「它是什么、别和谁搞混」。

| 术语 | 是什么 | 不要搞混成 |
|---|---|---|
| ChatBot | 根据上文生成下文，不调用外部程序 | 接了一次搜索的产品不一定是 Agent，可能只是固定流程 |
| Agent | 模型决定下一步，程序执行工具，把结果追加进上下文，再决定 | 不是更会聊天的模型 |
| 工具 Tool | 一段你写的函数，加上给模型看的名字、说明、参数表 | 不是模型自己跑起来的代码 |
| Function Calling | 模型输出「想调哪个函数、参数是什么」的结构化消息 | 不是模型去执行函数 |
| JSON Schema | 参数的类型、必填项、说明。模型按这张表填 | 不是业务数据本身 |
| tool_call_id | 一次调用的编号。工具结果必须带同一个编号回去 | 不是工具的名字 |
| ReAct | 想一步、做一步、看结果，再想下一步 | 不是某个必须安装的库 |
| Plan-and-Execute | 先列出整张步骤表，再逐步做，失败时重做相关步骤 | 不是 ReAct 的别名 |
| Reflexion | 失败后用语言写「刚才错在哪」，再试。不更新模型参数 | 不是强化学习 |
| Workflow | 步骤顺序是人预先写好的，模型只在格子里填内容 | 自主性低于 Agent |
| Prompt | 发给模型的全部文本：角色、指令、上下文、示例、格式 | 不是只有用户那一句话 |
| System prompt | 角色、边界、有哪些工具、什么时候拒绝 | 不是用户消息 |
| Few-shot | 在上下文里放几个输入输出样例，让模型照着格式写 | 不是重新训练 |
| JSON mode | API 保证输出是合法 JSON，不保证字段对 | 不是 Schema 约束 |
| RAG | 先从资料库查出原文，再让模型基于原文回答 | 不是把资料训练进模型 |
| Embedding | 把一段文字变成向量，方向接近表示语义接近 | 不是词表里的 `nn.Embedding` 那一张可训练矩阵，但是同一类想法 |
| Chunk 切分 | 把长文切成小段再向量化，避免一段里塞太多主题 | 不是随便按固定字数切就结束 |
| 余弦相似度 | 看两个向量的夹角，不看长度 | 不是欧氏距离 |
| BM25 / 关键词检索 | 按词是否出现、出现多少来打分，对型号和编号敏感 | 不是向量检索 |
| 混合检索 | 向量一路加关键词一路，合并排序 | 不是换一个更大的向量模型 |
| 重排序 Rerank | 粗筛出几十段之后，用更细的模型再排，只把前几段给模型 | 不是再训练 LLM |
| 短期记忆 | 放在这一次上下文窗口里的对话和工具结果 | 不是向量库 |
| 长期记忆 | 跨会话存在外部，用到时再检索 | 不是把全部历史永远塞进 Prompt |
| 摘要压缩 | 上下文快满时，用模型把旧过程收成一段事实和未完成项 | 不是滑动窗口那种直接丢弃 |
| State | 一张节点共用的状态表 | 不是某一个节点的局部变量 |
| Node | 读状态、返回要写回的字段的函数 | 不是网络节点 |
| Edge | 这个节点做完去哪个节点。条件边看状态来选 | 不是流程图里的装饰线 |
| Checkpointer | 每一步把状态存下来，中断后按 thread_id 接着跑 | 不是聊天记录文件的别名 |
| 人审 Human-in-the-loop | 危险动作执行前暂停，等人确认 | 不是让人代替模型写 Prompt |
| 多智能体 | 多个模型角色，各带各的上下文，互相只传必要结论 | 不是把一个 Prompt 写得很长 |
| 流水线 | A 的产出是 B 的输入，顺序固定 | 自主性最低的协作，也最容易调试 |
| 主管-工人 | 一个角色负责分派和验收，其他角色执行 | 不是群聊 |
| MCP | 模型和工具之间的接口协议。服务端公布工具，宿主转发调用 | 不是 Agent 框架 |
| Host / Client / Server | 宿主是用户用的应用；客户端是连接器；服务端是工具提供方 | Client 不是「用户」 |
| A2A | Agent 和 Agent 之间的协议，用能力名片互相发现 | 不是 MCP 的新版本 |
| Prompt Injection | 外部内容（网页、邮件、检索结果）里藏指令，模型把它当成任务 | 不是用户在聊天框里骂模型 |
| 轨迹 Trace | 一次任务的 Thought / 工具调用 / 观察 / 最终回答全过程 | 不是只有最终答案 |
| LLM-as-Judge | 用另一个模型按评分细则给开放式回答打分 | 不是准确率 |
| 沙箱 | 跑模型写的代码的隔离环境：超时、少权限、坏了不影响主进程 | 不是「子进程」三个字就能代替权限控制 |
| 条件分布 \(p(y\mid x)\) | 在这次全部输入 \(x\) 之下，下一段输出的概率。改 Prompt、改观察，都是在改 \(x\) | 不是模型外面另有一条「服从指令」的通道 |
| 约束解码 | 生成时把不符合格式的下一个 token 掩掉，非法续写的概率变为 0 | 不是在 Prompt 里把格式再说一遍 |
| \(p^n\) | 每步做对的概率是 \(p\) 时，连续 \(n\) 步都做对的概率。用来估计长循环为什么容易断 | 不是某一次运行的精确预测 |
| KV cache | 已经算过的 Key 和 Value，避免每个新 token 都重算前面的注意力 | 不是一份会记住「意思」的隐藏记忆 |
| 双编码器 | 问题和文档分开变成向量，查询时只比向量。文档向量可以预计算 | 不是查询时问题和文档的词还在互相注意 |
| 交叉编码器 | 问题和文档拼成一条序列一起做注意力，再打一个相关分。用于几十条候选的重排 | 不是用来扫百万文档的那一路 |
| BM25 | 关键词打分：越稀有的词权重越大，同一个词重复出现的收益会饱和 | 不是向量相似度 |
| 信用分配 | 只有最终对错时，无法知道中间哪一步造成了这个结果 | 不是端到端成功率本身 |
| 支撑集 | 这一轮概率大于零、或解码器允许生成的那些动作。工具清单就是在规定它 | 不是服务端安装了哪些函数 |
