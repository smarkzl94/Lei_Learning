## 🧱 第 0 课：零基础补课（不懂这节，后面全是天书）

> 这一节假设你**只懂加减乘除**，把后面所有内容的地基打一遍。

### 0.1 数组就是一排格子

先忘掉"张量"这个吓人的词。想象一个格子，格子里存一个数，比如 `85`。

* **一排格子** = 一维数组。比如一个小组 5 个人的数学成绩：

```
[85, 92, 78, 60, 88]
```

它有 5 个格子，所以形状（shape）是 `(5,)`。形状的意思就是"每个方向上有几格"。

* **一张表格** = 二维数组（矩阵）。4 个学生 × 3 门课的成绩单：

```
            语文  数学  英语
学生0  [ [ 85,   92,   78 ],
学生1    [ 60,   88,   90 ],
学生2    [ 72,   75,   69 ],
学生3    [ 91,   83,   77 ] ]
```

这张表有 4 行 3 列，形状就是 `(4, 3)`。**shape 永远按"行, 列"读**，和看 Excel 表一模一样。

* **一摞表格** = 三维数组。给成绩单加"星期"：4 学生 × 3 课 × 5 天，形状 `(4, 3, 5)`。你可以想象成一摞 5 张表格。

* **一摞摞表格** = 四维数组。再加"班级"：8 个班，每班一摞 5 张表，形状 `(8, 4, 3, 5)`。

**张量 = 任意维度的数组。** 标量、向量、矩阵只是 0 维、1 维、2 维的特例。所谓"4 维张量"不神秘，就是"格子按 4 个方向排"。

### 0.2 张量在电脑内存里其实是一排长条格子

这一点是理解 view/reshape 的钥匙。电脑内存是**一长条**的，不管几维数组，存的时候都是挨个铺平：

```
表格 [[a, b, c],
      [d, e, f]]
      ↓ 存进内存
长条 [a, b, c, d, e, f]
```

shape `(2, 3)` 只是一张"说明书"，告诉程序"每 3 个数切成一组，共切 2 组"。**换 shape 往往只是换说明书、不动格子里的数据**——这就是为什么 `view` 和 `reshape` 几乎不花时间。

那什么时候会出问题？如果你先把数据"翻个面"（permute 换维度顺序），内存里的长条还是 `[a, b, c, d, e, f]`，但新说明书要求按别的顺序读，对不上了——这时就得先把数据重新排一遍（contiguous 复制一份），才能换说明书。这就是第 4 节 view 报错的原因。

### 0.3 矩阵乘法到底在算什么（最重要！）

后面到处都在写 `y = x @ W`，`@` 就是矩阵乘法。它到底在干嘛？一句话：**每个结果格子 = 一行 × 一列，对应位置相乘再相加**。

拿成绩单举例。假设三门课要折算成一个"综合分"，权重是 语文 0.3、数学 0.5、英语 0.2：

```
学生0的综合分 = 85×0.3 + 92×0.5 + 78×0.2 = 87.1
```

这个"对应相乘再相加"的动作，就是矩阵乘法的基本单元。

推广一下：`(4, 3) @ (3, 2)` 能乘，是因为**左边的列数 = 右边的行数**（都是 3），结果形状是 `(4, 2)`——4 个学生，每人算出 2 种不同的综合分（比如再按另一套权重算一个"偏科分"）。

放到神经网络里：`x (64, 784) @ W (784, 128)`，含义是 **64 个样本，每个样本拿自己的 784 个特征，去和 128 个神经元各自的 784 个权重"对应相乘再相加"，算出 128 个分数**。左边列数 = 右边行数 = 784，对上就能乘，结果 `(64, 128)`。

对比记忆：

* `*` 是两个形状一模一样的表格，**对应格子**相乘（语文乘语文、数学乘数学）——很少用到

* `@` 是一行乘一列算出分数——**神经网络的主力**

### 0.4 广播：让"一张表格 + 一行数字"成立

接着成绩单说。现在要给每人每门课**都加 5 分平时分**：

```
[ [ 85+5,  92+5,  78+5 ],
  [ 60+5,  88+5,  90+5 ], ... ]
```

正常情况表格和表格才能相加，但这里右边只有一个数 `5`——程序自动把它**复制成一张同样大小的表**再相加。这就是广播：形状不一样时，把"长度为 1 或缺的"那个维度**自动补齐**。

`b = torch.randn(128)` 加到 `(64, 128)` 上，就是给 64 个样本的同一列都加上同一个偏置。你不用写循环，程序帮你复制。

### 0.5 本节只需要记住三句话

1. 张量 = 任意维的格子数组，shape 就是"每个方向几格"
2. 内存里永远是一排长条，shape 是切法说明书
3. `@` 矩阵乘 = 一行乘一列、对应相乘再相加

## 📚 核心知识点

### 1. 什么是张量

张量是 PyTorch 的核心数据结构，本质上是**可自动求导、可跑在 GPU 上的多维数组**。

**为什么是"多维数组"而不是别的？** 因为神经网络的数据天然是多维的：一张灰度图是 2 维（高×宽），一批彩色图是 4 维，一段文字序列也是 2 维（长度×词向量维度）。数组是表达"规则网格数据"的最自然结构，而标量/向量/矩阵只是它的低维特例。

| 维度  | 名称 | 例子      | shape               |
| --- | -- | ------- | ------------------- |
| 0 维 | 标量 | 损失值     | `()`                |
| 1 维 | 向量 | 偏置 bias | `(features,)`       |
| 2 维 | 矩阵 | 权重矩阵    | `(in, out)`         |
| 3 维 | 张量 | 序列/特征图  | `(seq, batch, dim)` |
| 4 维 | 张量 | 图像批次    | `(N, C, H, W)`      |

**为什么图像格式是 (N, C, H, W) 而不是 (N, H, W, C)？**

* **N（Batch）在最前**：神经网络几乎从不一次只处理一张图，而是批量处理。把批量维放最前面，取 `x[0]` 就能拿到第一张图，符合直觉。

* **C 紧挨着 N**：CNN 的卷积核是"按通道滑动"的运算，把通道放在紧邻批次的维度上，内存中通道数据连续存放，卷积访存最快。这是 PyTorch/CUDA 内部优化决定的约定（TensorFlow 用 NHWC 是另一套历史原因）。

* 记住就行：**PyTorch 里图像永远是 NCHW**，从 OpenCV/PIL 读进来的图 (H, W, C) 要 `permute(2, 0, 1)` 才能喂给模型。

> **记忆**：图像在 PyTorch 里永远是 `(批次, 通道, 高, 宽)` 即 NCHW 格式。

### 2. 创建张量

```python
import torch

torch.tensor([[1, 2], [3, 4]])        # 从数据创建
torch.zeros(3, 4)                     # 全 0
torch.ones(2, 3)                      # 全 1
torch.rand(2, 3)                      # [0,1) 均匀分布
torch.randn(2, 3)                     # 标准正态分布（权重初始化常用）
torch.arange(0, 10, 2)                # [0, 2, 4, 6, 8]，前闭后开
torch.linspace(0, 1, 5)               # 等间距 5 个数：[0, 0.25, 0.5, 0.75, 1]
x.new_ones(2)                         # 继承 x 的类型和设备
torch.full((2, 3), 7)                 # 填充指定值
```

**为什么这么多种创建方式？**

* `rand` vs `randn`：`rand` 是均匀分布（用于生成概率类的随机数），`randn` 是均值为 0、方差为 1 的标准正态分布（**权重初始化用它**，因为神经网络希望初始权重围绕 0 小幅波动）。

* `arange` vs `linspace`：`arange(0, 10, 2)` 按**步长**取（结果个数不确定）；`linspace(0, 1, 5)` 按**个数**取（步长自动算）。要精确控制点数用 linspace，要精确控制间隔用 arange。

* `x.new_ones(...)` 的价值：不用关心 x 是 float32 还是 float64、在 cpu 还是 cuda，**自动继承**——写通用代码时少踩设备/类型的坑。

### 3. 常用属性与类型

```python
x = torch.randn(2, 3)
x.shape      # torch.Size([2, 3])
x.dtype      # torch.float32（默认浮点类型）
x.device     # cpu 或 cuda:0
x.requires_grad  # 是否追踪梯度

# 类型转换
x.float()  x.long()  x.half()
x.to(torch.float64)
```

**为什么默认 float32 而不是 float64？** 深度学习对精度不敏感（权重本来就是近似值），但显存/内存很贵。float32 占用 4 字节，float64 占 8 字节——模型动辄百万参数，省一半内存意味着能开更大的 batch。甚至业界还在往 float16（2 字节）推。

常用 dtype 及**为什么**：

* `float32`：默认，所有计算的标准类型

* `float16`：混合精度训练，省显存提速度（第 13 章细讲）

* `int64/long`：**索引和标签强制要求这个类型**。`cross_entropy` 的标签、索引张量都必须是 long，传 int32 会直接报错——这是最常见的报错来源

* `bool`：掩码（任务 4 会用到）

### 4. 形状操作（高频）

```python
x = torch.randn(4, 3, 32, 32)

x.view(4, -1)          # 改变形状，-1 自动推断 → (4, 3072)
x.reshape(12, 32, 32)  # 与 view 类似，但允许非连续内存
x.flatten(1)           # 从第 1 维开始展平 → (4, 3072)
x.permute(0, 2, 3, 1)  # 维度换序 NCHW→NHWC
x.transpose(1, 2)      # 交换两个维度
x.squeeze()            # 去掉所有长度为 1 的维
x.unsqueeze(0)         # 在第 0 维增加一维
x.unsqueeze(0).expand(8, -1, -1, -1)  # 扩展（不复制内存）
```

#### 🔑 详解：`view(4, -1)` 为什么这么写

**`-1` 是"你帮我算"的意思。** `view(4, -1)` 说的是："第一维我要 4，剩下的维度你根据总元素数自动推断"。

为什么需要它？因为手动算很容易错。总元素数 = 4×3×32×32 = 12288，除以 4 得 3072——这个口算不难，但真实模型里 shape 是 `(32, 64, 7, 7)` 这种，你很难心算，而且万一前面某一步 shape 变了，硬编码的数字就悄悄错了。**用 `-1` 让程序自己算，永远不出错。**

规则：`-1` 只能出现一次（出现两次就有无数种拆分方法，程序没法推断）。`view(-1)` 单独用表示"不管几维，全部摊平成一维"。

```python
x.view(4, -1)     # (4, 3072)  ✅ -1 唯一，可推断
# x.view(-1, -1)  # ❌ 报错：只能有一个 -1
```

#### 🔑 详解：view 和 reshape 到底差在哪

**一句话：view 要求内存连续，reshape 不要求。**

张量在内存里其实是一维的"长条"，shape 只是"怎么切分这个长条"的视图。比如 `(2, 3)` 的张量内存是 `[a b c d e f]`，shape 告诉你"每 3 个一组，分 2 组"。

* `view` 只是**换切法**，不重排内存。所以换出来的切法必须和内存长条的顺序一致（即"连续"）。

* `permute`（维度换序）会让内存顺序和 shape 对不上（非连续），这时 `view` 会报错：

```python
x = torch.randn(4, 3, 32, 32)
xp = x.permute(0, 2, 3, 1)     # NCHW → NHWC，非连续了
# xp.view(4, -1)               # ❌ RuntimeError: view size is not compatible
xp.reshape(4, -1)              # ✅ reshape 会先偷偷 .contiguous() 复制一份再切
xp.contiguous().view(4, -1)    # ✅ 等价写法
```

**实践建议**：记不清就用 `reshape`，它内部能 view 就 view，不能就自动处理，性能几乎无差。等遇到报错再回头理解 view 也不迟。

#### 🔑 详解：squeeze / unsqueeze / expand

这三个是一组，都在操作"长度为 1 的维度"：

* `unsqueeze(0)`：加一个长度为 1 的维。**为什么需要？** 比如模型要求输入是 `(N, C, H, W)` 4 维，你只有一张 `(C, H, W)` 的图，差一个 batch 维，就 `unsqueeze(0)` 变成 `(1, C, H, W)`——"假装成一个 batch 里有 1 张图"。

* `squeeze()`：删掉长度为 1 的维，反向操作。比如模型输出 `(1, 10)`，你要的只是 10 个类别分数，`squeeze()` 变 `(10,)`。

* `expand(8, -1, -1, -1)`：把一个长度为 1 的维"撑大"到 8。**关键：不复制内存**，只是让 8 个位置都"看向"同一份数据。所以 `(1, C, H, W).expand(8, ...)` 瞬间完成，而 `repeat` 会真复制 8 份、慢且占内存。

### 5. 索引与切片

规则与 NumPy 完全一致：

```python
x[0]            # 第 0 个样本
x[:, 0]         # 所有样本的第 0 通道（: 表示"全都要"）
x[1:3, :, 8:24] # 组合切片
x[x > 0]        # 布尔掩码：返回满足条件的元素（压平成 1 维）
idx = torch.tensor([0, 2])
x[idx]          # 花式索引：按索引张量取，结果形状跟 idx 走
torch.masked_select(x, x > 0)
torch.gather(x, dim, index)   # 按索引收集（分类任务取概率常用）
```

**为什么是 `[:, 0]` 这种写法？** 逗号分隔的是"每个维度怎么取"。`x` 是 `(4, 3, 32, 32)` 时，`x[:, 0]` 的意思是：第 0 维全取（`:`），第 1 维只要第 0 个，第 2、3 维没写默认全取 → 结果 `(4, 32, 32)`。从左到右的每个位置对应 shape 里从左到右的每个维。

**布尔掩码 `x[x > 0]` 的原理**：`x > 0` 先生成一个和 x 形状相同的 bool 张量（True/False），然后"取"出所有 True 位置上的元素——结果一定是 1 维的，因为满足条件的元素个数事先不知道，没法保持原形状。

### 6. 数学运算

```python
# 逐元素运算
a + b   torch.add(a, b)
a * b   # 逐元素乘（不是矩阵乘！）
a @ b   torch.matmul(a, b)    # 矩阵乘法
a.pow(2)  a.sqrt()  a.exp()  a.log()

# 聚合运算
x.sum()  x.mean()  x.max()  x.min()
x.sum(dim=1)          # 沿维度聚合，维度会消失
x.sum(dim=1, keepdim=True)  # 保留维度（便于广播）
x.argmax(dim=1)       # 分类预测最常用

# 比较
torch.eq(a, b)  (a > b)
torch.topk(x, k=5, dim=1)     # Top-5 准确率用
```

#### 🔑 详解：`*` 和 `@` 为什么是两个符号

这是 NumPy/MATLAB 时代就留下的约定：

* `*` 是**逐元素**乘（Hadamard 积）：`[[1,2],[3,4]] * [[1,2],[3,4]] = [[1,4],[9,16]]`，形状必须相同（或可广播）。

* `@` 是**矩阵乘法**：`(m, k) @ (k, n) → (m, n)`，前一个的列数必须等于后一个的行数。

**神经网络里 99% 的情况是 `@`**（线性层 y = xW + b）。如果你算出结果 shape 不对，先检查是不是把 `@` 写成了 `*`。

#### 🔑 详解：聚合时的 `dim` 和 `keepdim`

`dim` 的意思是"**沿哪个维度压缩掉**"：

```python
x = torch.randn(4, 3)
x.sum()            # 标量：所有元素加总
x.sum(dim=0)       # (3,)：把第 0 维（4 个样本）压掉，得到"每列的总和"
x.sum(dim=1)       # (4,)：把第 1 维压掉，得到"每个样本 3 个特征的总和"
```

**`keepdim=True` 为什么存在？** 因为后续还要广播运算时，维度对不上会报错：

```python
x = torch.randn(4, 3)
m = x.mean(dim=1)               # (4,)
# x - m                         # ❌ (4,3) 和 (4,) 广播失败
m = x.mean(dim=1, keepdim=True) # (4, 1)
x - m                           # ✅ (4,3) - (4,1)，第 1 维广播成 3
```

一句话：**压掉的维度要参与后续广播，就 keepdim=True**。

`max` 和 `argmax` 是一对：`max` 返回值，`argmax` 返回位置。分类预测里 logits `(8, 10)`，`argmax(dim=1)` 给出每个样本预测的是第几类。

### 7. 广播机制（Broadcasting）

形状不同的张量运算时自动扩展，规则：**从右往左对齐维度，维度为 1 或缺失的可广播**。

```python
x = torch.randn(4, 3)     # (4, 3)
b = torch.randn(3)        # (3,) → 广播成 (4, 3)
x + b                     # 合法

x = torch.randn(4, 1)
y = torch.randn(1, 3)
x + y                     # (4, 3) 双向广播
```

#### 🔑 详解：广播为什么是这么个规则

广播的目标：**让"一个矩阵 + 一个向量"这种数学上合法、手写循环又很蠢的操作，一行代码完成**。

规则拆解（拿 `(4, 3) + (3,)` 举例）：

1. **从右往左对齐**：`(3,)` 对到 `(4, 3)` 的最后一维 `3`。为什么从右？因为右边是小维度（特征维），加法天然是"每个位置的数相加"，小维度先对齐才符合语义。
2. **缺失的维视为 1**：`(3,)` 前面补一个 1，变 `(1, 3)`。
3. **长度为 1 的维可以"复制撑大"**：`(1, 3)` 的第 0 维撑成 4 → `(4, 3)`，再相加。

所以 `x + b` 的实际含义是：b 这一组偏置，**加到每一个样本上**——这正是线性层 y = xW + b 里 b 的作用，一行代码搞定，不用写循环。

**什么时候会报错？** 对齐后某维一个是 2、一个是 3（都不是 1），无法协调，报错。比如 `(4, 3) + (4,)` 不合法（`4` 对不上 `3`），但 `(4, 3) + (3,)` 合法。

### 8. GPU 加速

```python
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')

x = x.to(device)              # 张量上 GPU
model = model.to(device)      # 模型上 GPU

# 注意：运算双方必须在同一设备
# cpu_tensor + cuda_tensor → RuntimeError
```

**为什么要手动 `.to(device)`？** 因为 GPU 和 CPU 是两套物理内存，数据搬过去要花时间（这也是小模型在 GPU 上反而慢的原因——搬运开销 > 计算收益）。PyTorch 不会偷偷帮你搬，它选择让你显式控制，这样你能知道数据在哪、搬了几次。

`.to()` 的妙处：如果张量已经在目标设备，它是 no-op（什么都不做），所以可以无脑调用。

> 💡 你现在的环境是 CPU 版 torch，`cuda.is_available()` 是 False——跑小练习完全够，等真训练模型再装 CUDA 版。

### 9. 与 NumPy 互转

```python
import numpy as np
a = np.array([1, 2, 3])
t = torch.from_numpy(a)   # 共享内存！改一个另一个也变
b = t.numpy()             # 仅 CPU 张量可直接转
```

**为什么 `from_numpy` 共享内存？** 因为"复制"是有成本的。一段 4GB 的数据，复制一遍就是 4GB 内存 + 时间开销。PyTorch 的哲学是：默认零拷贝（共享内存），你要独立副本就显式 `.clone()` 或 `torch.tensor(a)`（这个会复制）。这在数据预处理 pipeline 里很常见——OpenCV 读的图是 numpy，直接 from\_numpy 包成张量，不花一分钱拷贝。

判断方法：改一个看另一个变没变（任务 5 就是在验证这个）。

> ⚠️ `from_numpy` 共享内存是特性也是坑，需要独立副本时用 `.clone()`。

## ⚠️ 常见坑

1. `view` 要求内存连续，报错乱用前先 `.contiguous()`，或直接用 `reshape`（它内部自动处理）
2. 默认 `float32`，而标签索引要 `long`，类型不匹配是最常见报错（`cross_entropy` 标签必须是 long）
3. `torch.dot` 只能算 1 维向量点积；矩阵乘法用 `@` / `matmul`
4. 设备不一致：`模型在 cuda、数据在 cpu` 会直接报错
5. `x * W` 写出逐元素乘了——矩阵乘是 `@`，算出来 shape 不对先查这个
6. `unsqueeze` 和 `squeeze` 搞混：squeeze 是"删 1"，unsqueeze 是"加 1"

## 📝 小结

* 张量 = 多维数组 + 自动求导 + GPU；图像永远 NCHW
