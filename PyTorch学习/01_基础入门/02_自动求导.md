## 🧱 第 0 课：零基础补课（导数和梯度是什么）

> 没学过微积分也看得懂，用"下山"这一个例子讲透。

### 0.1 导数：坡度就是方向

想象你在山里，要走到最低点（对应深度学习：让 loss 最小）。

- **导数是什么？** 你站的地方，地面的**坡度**。坡度为正说明往上走是升的，为负说明往上走是降的。
- **它告诉你两件事**：① 该往哪个方向走（坡度的反方向）；② 坡有多陡（坡度的绝对值，决定迈多大步）。
- **怎么算？** 不需要真的推公式，PyTorch 自动帮你算。你只需要会**问**：loss 对某个参数的导数是多少？

### 0.2 梯度：每个参数各自的坡度

实际模型里不止一个参数，有成千上万个（W、b……）。**梯度 = 所有参数各自的导数组成的向量**。

每个参数都得到一个数字，含义统一：

> 这个参数**变大一点，loss 会变大还是变小？变多快？**

- 梯度是 **+5**：参数调大 loss 会涨 → 那就往**小**调
- 梯度是 **-3**：参数调大 loss 会降 → 那就往**大**调
- 调整量 = 学习率 × 梯度（学习率是人为定的步长）

训练循环的本质就一句话：**反复问每个参数"你该怎么调"，然后调一点**。

### 0.3 链式法则： blame 的回传

模型是多层的：`x → 第1层 → 第2层 → ... → loss`。loss 对第 1 层参数的导数怎么算？数学上的**链式法则**说：

```
∂loss/∂第1层参数 = ∂loss/∂上一层输出 × ∂上一层输出/∂第1层参数
```

直观理解：**责任一层层往回推**——loss 先怪最后一层，最后一层算出"我负多少、我的输入负多少"，再往前传，一直传到第一层。这个"回传责任"的过程就叫**反向传播（backpropagation）**。

PyTorch 的 autograd 干的就是这件事：你前向算一遍 loss，调用 `loss.backward()`，所有参数的梯度自动算好，放在各自的 `.grad` 里。

## 📚 核心知识点

### 1. 为什么需要自动求导

深度学习训练 = 前向算损失 + **反向算梯度** + 更新参数。手动推导每层梯度不现实，PyTorch 的 **autograd** 通过动态计算图自动完成反向传播。

```
前向：x → [运算] → y → [运算] → loss   （边算边建图）
反向：loss → ∂loss/∂y → ∂loss/∂x       （链式法则，沿图回传）
```

**"动态计算图"是什么？** 图就是"谁由谁算出来"的记录。动态的意思是：**PyTorch 不是事先画好图，而是你每做一次运算，现场记一笔**。所以你可以用 Python 的 if/for 随意控制流程，图跟着你的代码走（对比：TensorFlow 早期是静态图，先画好再跑，灵活但难调试——这也是 PyTorch 赢得研究界的原因之一）。

### 2. requires_grad：让张量被追踪

```python
import torch

x = torch.tensor([2.0], requires_grad=True)  # 声明：我要对 x 求导
y = x ** 2 + 3 * x
y.backward()          # 反向传播，y 是标量时无需传参
print(x.grad)         # dy/dx = 2x + 3 = 7.0
```

拆解这条代码链发生了什么：

1. `requires_grad=True`：给 x 打开"录音"（第 01 章提过这个开关）
2. `y = x**2 + 3*x`：每个运算都被录下来，悄悄形成一张图：`x → x² → +3x → y`
3. `y.backward()`：沿图反向走一遍，用链式法则算出**每个被录音张量**的梯度，存进 `.grad`
4. `x.grad`：取出来看——数学上 y 对 x 的导数是 2x+3，x=2 时确实是 7

- 只有 `requires_grad=True` 的张量参与建图
- 模型参数（`nn.Parameter` / 各层权重）默认 `True`
- 只有**浮点类型**才能求导（int 张量开录音会报错——回忆第 01 章的 dtype）

### 3. backward() 的规则

```python
# 情况1：标量（loss）直接 backward
loss.backward()

# 情况2：非标量必须传 gradient 参数
y = x ** 2              # y 是向量
y.backward(torch.ones_like(x))   # 等价于对 y.sum() 求导
```

**为什么非标量要传参数？** backward 的语义是"这个张量对 loss 的贡献权重"。标量 loss 的权重自然是 1，不用传。向量 y 有多个分量，程序不知道你要的是"每个分量分别对总 loss 的影响"，传 `ones` 就是告诉它"把它们当作求和整体对待"。

日常 99% 的情况你 backward 的对象就是 loss（标量），情况 2 先有个印象即可。

### 4. 梯度累积与清零（最高频的坑）⭐

PyTorch 的梯度是**累加**的，不会自动覆盖：

```python
for data, target in loader:
    output = model(data)
    loss = criterion(output, target)

    optimizer.zero_grad()   # ← 必须！否则梯度越加越大
    loss.backward()         # 梯度累加到 .grad
    optimizer.step()        # 用梯度更新参数
```

**为什么设计成累加而不是覆盖？** 官方理由是支持"梯度累积"技巧（见下），但副作用就是——不清零，第二轮算出的梯度会**叠在上一轮的结果上**，loss 下降异常、甚至梯度爆炸。

> 忘写 `zero_grad()` 是新手第一大坑。记住训练五步口诀：
> **`zero_grad → forward → loss → backward → step`**

梯度累积也可用来**模拟大 batch**（显存不够装不下大 batch 时，几个小 batch 的梯度攒起来再更新）：

```python
accum_steps = 4
for i, (data, target) in enumerate(loader):
    loss = model(data).sum() / accum_steps
    loss.backward()                      # 故意不清零，梯度累加
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

### 5. 三件套：no_grad / detach / requires_grad_(False)

| 需求 | 用法 | 场景 |
|------|------|------|
| 临时不求导 | `with torch.no_grad():` | **验证/测试**时包住整个前向 |
| 永久不求导 | `param.requires_grad_(False)` | 冻结预训练模型的部分层 |
| 从图中拆出来 | `x = y.detach()` | 把张量当纯数据用（共享内存） |

```python
# 验证阶段标准写法
model.eval()
with torch.no_grad():          # 不建图，省显存、加速
    for data, target in test_loader:
        output = model(data)

# 微调时冻结 backbone
for param in model.backbone.parameters():
    param.requires_grad_(False)
```

**区别在哪？**
- `no_grad()` 是**作用域**：在它里面做的所有运算都不录音，出了作用域恢复
- `requires_grad_(False)`（注意下划线，是**原地修改**）是**给某个参数摘掉录音开关**，之后都不录，用于微调时冻结不想动的层
- `detach()` 是**复制一个"失忆"的分身**：值一样、共享内存，但从此跟计算图无关。常用来"把算出来的中间值当普通数据用"

### 6. 计算图的生命周期

- `backward()` 后计算图**默认被释放**，再次对同一图 backward 会报错
- 需要多次反向时：`loss.backward(retain_graph=True)`
- 训练循环中每次迭代都会重新前向、**重新建图**，所以正常循环不受影响

### 7. 查看梯度与调试

```python
print(model.fc1.weight.grad)          # 看参数梯度
x.grad_fn                              # 看创建该张量的运算
x.is_leaf                              # 是否叶子节点

# 梯度为 None 的常见原因：
# 1. 没写 requires_grad=True
# 2. 中间用了 detach() / .item() / numpy() 断开了图
# 3. 该参数没参与 loss 的计算
```

`.item()` 把单元素张量转成 Python 数值，用于记录 loss：

```python
total_loss += loss.item()   # 对！断开图，只取数值
total_loss += loss          # 错！拖着整个计算图，显存泄漏
```

**为什么第二种写法是泄漏？** loss 还连着整张计算图（录音带还在），累加它等于把每一轮的录音带都存进内存，越攒越多。`.item()` 相当于撕下分数、扔掉录音带。

## 💻 实战练习

练习文件：`D:\DemoPy\practice\practice02.py`（5 个任务，对应本章知识点）

```python
# 核心练习：手动实现一次完整的参数更新（不用 optimizer）
w = torch.tensor([1.0], requires_grad=True)
lr = 0.1

for epoch in range(10):
    loss = (w * 3 - 9) ** 2      # 目标：让 w 趋近 3
    loss.backward()
    with torch.no_grad():         # 更新参数时不能建图
        w -= lr * w.grad
    w.grad.zero_()                # 清零，准备下一轮

print(w.item())  # ≈ 3.0
```

## ⚠️ 常见坑

1. 训练循环忘 `optimizer.zero_grad()` → 梯度累积
2. 验证循环忘 `torch.no_grad()` → 显存爆炸
3. 记录 loss 直接加张量不加 `.item()` → 内存泄漏
4. 用 `x.data` 绕过图（老代码）→ 改用 `detach()` 更安全

## 📝 小结

- 梯度 = 每个参数的"坡度"，告诉你往哪调、调多少
- autograd = 前向动态建图 + 链式法则反向传播，backward 后梯度在 `.grad` 里
- 训练五步：`zero_grad → forward → loss → backward → step`
- 验证必包 `no_grad`，取数值用 `.item()`
