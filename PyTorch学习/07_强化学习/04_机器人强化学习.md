## 📚 核心知识点

### 1. 为什么机器人需要 RL

传统控制（PID、MPC）需要精确建模，但真实机器人面对：

- 接触力学难建模（行走时脚的碰撞）
- 环境多变（地形、载荷、磨损）
- 高维连续控制（几十个关节协调）

RL 的思路：**不建模，直接在仿真里试错上亿次，学出控制策略**。 legged robot（四足/人形）近年的爆发主要靠这条路线。

### 2. 机器人 RL 的三要素设计

**状态 s（观测）**：机器人"感觉"到什么

```python
obs = [
    base_angular_vel,      # 机身角速度（陀螺仪）
    projected_gravity,     # 重力在机身上的投影（姿态）
    joint_positions,       # 各关节角度（编码器）
    joint_velocities,      # 各关节角速度
    commands,              # 期望速度指令（遥控输入）
    last_actions,          # 上一时刻动作（平滑性）
]
```

**动作 a**：策略输出各关节的**目标位置/力矩**，底层 PD 控制器执行：

```python
# 动作 → PD 控制 → 力矩
torque = kp * (action * scale + default_pos - joint_pos) - kd * joint_vel
```

> 不直接输出力矩而输出目标位置，是学习稳定性的关键工程技巧。

**奖励 r（最考验设计功力）**：

```python
reward = (
    + 1.0 * tracking_lin_vel      # 跟踪指令速度（主任务）
    + 0.5 * tracking_ang_vel
    - 0.005 * torque_penalty       # 省电
    - 0.1 * action_rate_penalty    # 动作平滑（防抖动）
    - 0.05 * orientation_penalty   # 机身保持水平
    + alive_bonus                  # 没摔倒
)
```

> 奖励 = "要什么 - 别怎么样"。稀疏奖励学不动，稠密奖励易钻空子（reward hacking）。

### 4. Sim-to-Real：仿真到现实的鸿沟

仿真和现实的差异（动力学误差、传感器噪声、延迟）会让策略真机失效。对策：

**域随机化（Domain Randomization）——最重要的技术**：

```python
# 训练时每次 reset 随机化物理参数
friction = uniform(0.3, 1.5)         # 地面摩擦
mass = base_mass * uniform(0.8, 1.2) # 质量扰动
motor_strength = uniform(0.9, 1.1)
obs += noise(0.02)                    # 传感器噪声
push_robot_randomly()                 # 随机踹一脚（抗扰）
```

直觉：在"一万种略有差异的世界"里都走得好，现实世界大概率也能走。

其他手段：系统辨识（标定真实参数）、域适应、真实数据微调。

### 5. 完整技术栈

```
URDF 模型 → 仿真环境(Isaac Lab) → 并行采集 → PPO 训练
→ 策略导出(ONNX/JIT) → 部署到真实机器人(C++/ROS 节点实时推理)
```

```python
# 部署：策略就是一个前向网络，10ms 一次推理
obs = get_sensor_obs()
```

## 💻 实战练习

```python
# 用 stable-baselines3 + MuJoCo 体验连续控制（PPO 主场）
from stable_baselines3 import PPO
import gymnasium as gym

env = gym.make('Pendulum-v1')            # 连续动作：扭矩 [-2, 2]
model = PPO('MlpPolicy', env, verbose=1)
model.learn(total_timesteps=100000)
# 观察回报曲线从 -1500 爬升到 -200 左右
```

## ⚠️ 常见坑

1. 奖励设计不平衡 → 机器人学会"趴着不动拿 alive bonus"
2. 没做域随机化 → 仿真满分、真机秒摔
3. 动作直接输出力矩 → 训练发散，用目标位置 + PD
4. 观测里没有历史信息 → 策略学不到速度趋势，加 last_actions
