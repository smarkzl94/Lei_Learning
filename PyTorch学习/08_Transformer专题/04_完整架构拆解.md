## 📚 核心知识点

### 1. 一个 Encoder Block 的四个零件

零件都见过了：多头注意力（专题-03）、残差连接（04 章）。组装起来：

```
输入 x
  │
  ├──────────────┐
  ▼              │
Multi-Head       │
Attention        │ 残差①
  │              │
  ▼              ▼
  Add( +x ) & LayerNorm
  │
  ├──────────────┐
  ▼              │
FFN              │ 残差②
(Linear→ReLU→Linear)
  │              │
  ▼              ▼
  Add( +x ) & LayerNorm
  │
  ▼ 输出（和输入同形状）
```

**数据流口诀：子层 → 加残差 → 归一化，两遍。**

形状全程不变：`(batch, seq, d_model)` 进，`(batch, seq, d_model)` 出——这就是能无限堆叠的原因（原版 6 层，GPT-3 是 96 层）。

### 2. FFN：每个词单独过的小 MLP

```python
FFN = nn.Sequential(
    nn.Linear(d_model, 4 * d_model),   # 512 → 2048，先扩张
    nn.ReLU(),                          # （现代用 GELU/SwiGLU）
    nn.Linear(4 * d_model, d_model),   # 2048 → 512，再压回
)
```

- 注意力负责**词与词之间**交换信息；FFN 负责**每个词内部**消化信息——先扩 4 倍"摊开思考"，再压回去
- 每个词独立过同一个 FFN（序列维上没有交互）
- 参数量上 FFN 占整个 block 的约 2/3——**Transformer 的"知识"主要存在 FFN 里**

### 3. LayerNorm：BatchNorm 的序列版

04 章学的 BatchNorm 在 NLP 里不好使：一个 batch 里句子长短不一，跨样本统计没意义。

**LayerNorm 改为：对单个样本的特征维归一化**——每个词向量自己内部拉成零均值单位方差，与 batch 里其他样本无关。作用不变：稳住数值分布，深层网络训得动。

```python
nn.LayerNorm(d_model)   # 归一化最后一维（特征维）
```

### 4. Decoder：多块"交叉注意力"

原版 Transformer 是翻译模型，encoder 读源语言、decoder 生成目标语言。Decoder block 比 encoder 多一个子层：

```
Masked Self-Attention → Add&Norm      ← 只能看已生成的词（专题-05 详解）
Cross-Attention       → Add&Norm      ← Q 来自 decoder，K/V 来自 encoder 输出
FFN                   → Add&Norm
```

**Cross-Attention 是"查资料"**：decoder 每生成一个词，拿自己的 Q 去查 encoder 记下的整句原文（K/V）——翻译时"回看原句"的机制。

> 现代纯 GPT 类模型只有 decoder（堆 masked self-attention），BERT 类只有 encoder。理解两种 block 就理解了全部大模型。

### 5. PyTorch 组装

```python
import torch.nn as nn

# 一个 block
layer = nn.TransformerEncoderLayer(
    d_model=512, nhead=8,
    dim_feedforward=2048,      # FFN 中间维
    dropout=0.1,
    batch_first=True,
)
# 堆 6 层
encoder = nn.TransformerEncoder(layer, num_layers=6)

x = torch.randn(2, 10, 512)    # (batch, seq, d_model)
out = encoder(x)               # 形状不变：(2, 10, 512)
```

残差、LayerNorm、FFN 全封装在 `TransformerEncoderLayer` 内部——现在你知道里面每个零件是干嘛的了。

## 📎 扩读：Encoder、Decoder 与三大模型家族

**所有大模型用的是同一块积木**（残差 + LayerNorm + 注意力 + FFN），真正的差别只有一个：**注意力能往哪个方向看**。

```
原版 Transformer（2017，为翻译而生）
   ├─ 只留 Encoder + 双向注意力   → BERT、RoBERTa（理解任务）
   ├─ 只留 Decoder + 因果注意力   → GPT、LLaMA、Qwen（生成任务）
   └─ 两边都留，Cross-Attention 桥接 → T5、BART（翻译/摘要）
```

**核心差异：能不能看右边。** 以「我 爱 吃 苹果」为例：

- **Encoder（双向）**：算「吃」的表示时左右都能看——词义由整句语境决定，天然适合"这句话什么意思/什么情感/和另一句像不像"。
- **Decoder（因果/单向）**：算「吃」时只能看左边，「苹果」被下三角掩码（causal mask）挡死——真实写作时后面还没写出来，训练偷看等于考试翻答案，上线就露馅。causal mask 保证第 t 个位置只用第 1~t 的信息（专题-05 细讲）。

**为什么理解归 Encoder、生成归 Decoder：**

- 理解要"整句语义"：双向注意力让每个词看过全文，汇总后做分类/匹配顺理成章。配套训练方式是**完形填空**（MLM：随机挖词，根据左右猜回来）——BERT 的 [CLS] 位置常拿来做整句表示。
- 生成要"逐词往外吐"：训练目标是**下一个词预测**，与聊天/续写/写代码的用法一致，训练即用法。双向 Encoder 拿来自回归生成会"偷看未来"，先天不匹配。
- 边界在模糊：2022 年后业界全面倒向 decoder-only——理解任务也可以拼成 prompt 让 GPT 类生成答案，一个架构通吃。

**课程地图对照：**

| 家族 | 积木堆法 | 注意力视野 | 训练目标 | 代表 |
|---|---|---|---|---|
| Encoder-only | 堆 encoder block | 双向 | 完形填空（MLM） | BERT、RoBERTa |
| Decoder-only | 堆 masked decoder block | 只看左边 | 预测下一个词 | GPT、LLaMA、Qwen |
| Encoder-Decoder | 两边都堆 + cross-attention | 一边双向一边单向 | 序列到序列 | T5、BART、翻译模型 |

> 一句话总结：会了积木本身，再分清"双向"还是"因果"这一个开关，从 BERT 到 ChatGPT 的主线就全抓住了——剩下的差别是规模、数据和对齐技巧，不是骨架。

## ⚠️ 常见坑

1. 以为注意力是参数大头——其实 FFN 约占 2/3
2. `batch_first` 忘了设，PyTorch 默认 `(seq, batch, d_model)`，维度错位不报错但结果全错
3. LayerNorm 归一化维度写错：对特征维 `d_model`，不是对序列维
4. 堆叠层数加深但 loss 不降 → 检查残差是否真接上了（自己手写时最常断）

## 💬 课堂问答沉淀

**Q1：FFN 占 block 参数约 2/3，能算出来吗？**
以 `d_model=512、dim_feedforward=2048` 为例（均不含 bias）：
- FFN 两层 Linear：512×2048 + 2048×512 = **2,097,152**
- 注意力 Q/K/V/O 四个 512×512 投影：4×262,144 = **1,048,576**
- 2,097,152 ÷ (2,097,152+1,048,576) = **2/3**，说法成立。业界因此说"Transformer 的知识主要存在 FFN 里"。

**Q2：为什么 BatchNorm 在 NLP 里失灵、非要换 LayerNorm？**
BatchNorm 跨 batch 样本统计均值方差，但一个 batch 里句子长短不一、内容无关（"猫追老鼠"和"央行降准"），共享统计量没有意义。LayerNorm 改为对**每个词向量自己的特征维**归一化，与 batch 里其他样本无关。一句话：BatchNorm 竖着切（跨样本），LayerNorm 横着切（样本内部）。

## 📝 小结

- Block = 注意力 → Add&Norm → FFN → Add&Norm，形状不变可无限堆
- 注意力管词间交互，FFN 管词内消化（参数大头）
- LayerNorm 归一化特征维，BatchNorm 的序列替代
- Encoder 看全句，Decoder 多块 Cross-Attention 查原文
